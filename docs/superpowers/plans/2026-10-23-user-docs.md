# User Documentation Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish an operator-facing documentation site for mailer (about 44 pages, Coolify-scale) as a VitePress workspace `apps/docs`, deployed to GitHub Pages at `https://schwarzdavid.github.io/mailer/`, with the API reference rendered from the generated OpenAPI document, an environment reference guarded against drift, generated screenshots, and the README shrunk to an introduction with a link.

**Architecture:** A new workspace `apps/docs` holds the VitePress site (Markdown pages, `.vitepress/config.ts`, a theme that registers `vitepress-openapi`, small TypeScript scripts with Vitest tests for the conventions that keep the docs honest: sidebar ↔ pages, environment table ↔ `env.schema.ts`, API tags ↔ reference pages, screenshot references ↔ files). The stack bootstrapping of the frontend e2e suite moves into a shared package `packages/e2e-stack`, so both the Playwright e2e suite and the docs' screenshot run start the same throwaway stack. `backend#generate` additionally writes `env-keys.json`; `docs#build` depends on it. A new workflow `docs.yml` builds on every push and pull request and deploys on `main`.

**Tech Stack:** VitePress 1.6.4, vitepress-openapi 0.2.5, Vue 3.5, Vitest 4, Playwright 1.61 (`@playwright/test`), Testcontainers 12, nodemailer 9, Turborepo 2, pnpm 11, GitHub Pages actions.

**Spec:** `docs/superpowers/specs/2026-10-23-user-docs-design.md`. The spec's Site map (page list, content, sources per page) and its "Audience and quality bar" are part of every content task below; the plan does not repeat them.

- **Formatting:** Prettier owns it (`pnpm format:fix`): 4-space indent, single quotes, no semicolons, trailing commas, `package.json` with 2 spaces. Markdown is formatted by Prettier too; run it before every gate.
- **Repository and URLs:** GitHub repository `schwarzdavid/mailer`, Pages URL `https://schwarzdavid.github.io/mailer/`, VitePress `base: '/mailer/'`, edit link `https://github.com/schwarzdavid/mailer/edit/main/apps/docs/:path`, raw file URLs `https://raw.githubusercontent.com/schwarzdavid/mailer/<tag>/deploy/compose.yml`.

3. **A new controller gets a new `@ApiTags` value and the API reference silently lacks it.** Expected: the docs test fails and names the tag. _Pinned in Task 6: `scripts/__tests__/api-reference.spec.ts`._
